# مدار

نظام للشؤون الإدارية لمنشأة واحدة وفروعها، يُبنى على مراحل. يبدأ بالموظفين والإجازات والموافقات والرواتب.

طُبق الترحيل الأولي يدويًا بواسطة المستخدم، وطوبقت نتائجه وسجل Drizzle. بدأ بناء مسار تسجيل الدخول الأول في M3-02 بالعربية والإنجليزية، مع تغيير الكلمة المؤقتة والجلسات وحارس الصلاحيات والتدقيق الاحتياطي. حالة التحقق والقبول في WORK_PLAN.md؛ لا يعني وجود الواجهة إنشاء حساب ADMIN في القاعدة. يتولى المستخدم الرفع إلى GitHub والنشر على Railway.

تتضمن خطة الأساس التثبيت كتطبيق PWA والدخول والصلاحيات والترقيم والتدقيق ومعالجة الأخطاء. يبين سجل المهام ما تم تنفيذه وما خُطط له.

## التشغيل المحلي

يتطلب التشغيل Node.js 24. استُخدم Node.js 24.15.0 وnpm 11.12.1 في التحقق المحلي. إصدارات الحزم مثبتة في [package.json](package.json) و[ملف القفل](package-lock.json).

```powershell
npm.cmd ci
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd start
```

افتح [مدار المحلي](http://127.0.0.1:3000/). للوضع التطويري، شغّل `npm.cmd run dev:server` و`npm.cmd run dev:client` في نافذتين، ثم افتح `http://127.0.0.1:5173/`. يعيد مسار `/health` في الوضع المحلي حالة عدم جاهزية قاعدة البيانات، وتعرض شاشة الدخول عدم توفر الخدمة حتى تهيئة الاتصال والأسرار.

الوضع المحلي هو الافتراضي، ويستمع على عنوان الجهاز المحلي. يُضبط الوضع `connected` من بيئة الخادم عند تشغيله مع TiDB في البيئة المقصودة. توثق [.env.example](.env.example) أسماء المتغيرات. يقرأ الخادم قيمًا يمررها النظام أو مشغل الخدمة صراحة. [تصميم PWA والتشغيل](docs/PWA_AND_DEPLOYMENT_DESIGN.md).

## تفعيل مسار الدخول الأول

لا تُعاد الترحيلات المطبقة ولا تُنشأ حسابات تلقائيًا عند تشغيل التطبيق. فصل حساب اتصال القاعدة مؤجل وفق D-055، ولا يغير تشغيل هذه النسخة ذلك القرار.

1. داخل ملف .env المحلي المستبعد من Git، احتفظ باتصال DATABASE_URL إلى madar، واضبط MADAR_RUNTIME_MODE=connected وAPP_ORIGIN=http://127.0.0.1:3000 للتجربة المحلية. في النشر يكون APP_ORIGIN رابط HTTPS الفعلي دون شرطة نهائية. عند استخدام Vite منفصلًا يكون أصل الواجهة http://127.0.0.1:5173.
2. أضف AUTH_SECRET عشوائيًا خاصًا لا يقل عن 32 حرفًا. أضف MADAR_ADMIN_PASSWORD بكلمة مؤقتة خاصة من 15 إلى 128 حرفًا. لا ترسل هذه القيم في المحادثة ولا تضعها في المستودع.
3. نفذ مرة واحدة بإرادتك على القاعدة المقصودة: npm.cmd run db:bootstrap-admin. ينشئ ADMIN والدورين ومنحهما وحدث التدقيق بمعاملة. إذا وجد ADMIN لا يغير كلمته أو صلاحياته؛ وإذا كانت المنشأة مهيأة بحساب آخر فقط يتوقف دون الاستيلاء عليها. احذف MADAR_ADMIN_PASSWORD من .env بعد نجاح التهيئة، ولا تضعه في متغيرات خادم التشغيل اليومية.
4. بعد البناء شغّل: node --env-file=.env dist/server/index.mjs ثم افتح http://127.0.0.1:3000/، أو مرر المتغيرات إلى Railway وفق إعداد النشر. لا تُستخدم Cookie التطوير على أصل إنتاج HTTP.
5. ادخل باسم ADMIN وكلمته المؤقتة، ثم غيّر الكلمة قبل الوصول إلى الصفحة الداخلية. جرّب الخروج وإعادة التحميل وتبديل اللغة. لا صفحات موظفين أو إدارة حسابات في هذه الدفعة.

التجربة المتصلة بـTiDB وإنشاء الحساب الفعلي لا يُثبتان باختبارات التخزين البديل المحلية. تُسجل نتائج التنفيذ والرابط وقبول المستخدم في الخطة. دعم PWA يتضمن البيان والأيقونات وصفحة انقطاع عامة فقط؛ لا تخزن الجلسات أو ردود API في عامل الخدمة. التثبيت الفعلي على Android وiPhone والتحقق بعد النشر لهما بوابة اختبار مستقلة.

تولّد `npm.cmd run db:generate` ملفات SQL محليًا من تعريفات Drizzle. تُراجع حالة تطبيق الترحيل ومتطلبات تجربة TiDB في [مرجع السيكما](docs/DATABASE_SCHEMA.md).

التنظيم المعتمد يفصل client وserver وshared وقاعدة البيانات وdocs، ويقسم الملفات والجداول حسب الوحدات والوظائف، مع migrations واتصال ومعاملات مركزيين. تحفظ مفاتيح الاتصال والأسرار في متغيرات البيئة خارج الكود.

## نشر النسخة الحالية للتجربة على Railway

النسخة الحالية مسار الدخول الأول، ويحتاج النشر تحققًا بعد التشغيل وقبول المستخدم. يرفع المستخدم المصادر وملف القفل إلى GitHub، مع استبعاد .env وnode_modules وdist كما تحدد .gitignore. يرتبط Railway بالمستودع ويُبنى من جذر المشروع الذي يحتوي package.json.

| الإعداد | القيمة |
| --- | --- |
| Node.js | 24.x وفق package.json |
| Build Command | npm run build |
| Start Command | npm start |
| Healthcheck Path | /health |

تضاف في Variables: MADAR_RUNTIME_MODE=connected وNODE_ENV=production، وDATABASE_URL الخاص بقاعدة madar الحالية، وAUTH_SECRET الخاص المحفوظ محليًا، وAPP_ORIGIN كرابط HTTPS العام الفعلي للخدمة دون شرطة نهائية (لا يُنسخ أصل localhost للنشر). يمرر Railway المنفذ عبر PORT ويقرأه الخادم. الأسرار تُدخل في Variables فقط ولا تُرفع مع .env إلى GitHub. لا يُضاف MADAR_ADMIN_PASSWORD إلى بيئة التشغيل ولا أمر bootstrap أو ترحيل في Pre-deploy؛ الحساب والترحيل هُيئا بالفعل وفق نتائج المستخدم.

بعد النشر يشارك المستخدم الرابط لفحص الجاهزية والدخول وتغيير الكلمة والخروج واللغتين وPWA. فحص /health يثبت جاهزية الاتصال، ولا يكفي وحده لقبول مسار المستخدم. فصل حساب اتصال القاعدة ما زال مؤجلًا وفق D-055. لم يربط المساعد حساب GitHub أو Railway ولم ينشر الخدمة. [متغيرات Railway](https://docs.railway.com/variables)، [أمر التشغيل](https://docs.railway.com/deployments/start-command)، [فحص الجاهزية](https://docs.railway.com/deployments/healthchecks).

## تجربة إدارة المستخدمين — الدفعة الثانية من M3-02

بعد رفع التحديث إلى GitHub ونشره على Railway، افتح مدار بحساب مخول بـusers.manage واضغط «إدارة المستخدمين». المسار المباشر /users محمي بالتحقق من الجلسة والصلاحيات، والموارد البشرية ممنوعة افتراضيًا. لا متغيرات نشر جديدة أو ترحيل أو إعادة تهيئة ADMIN لهذه الدفعة.

لتجربة تصحيح شاشة التحقق: افتح نموذج إنشاء حساب وأدخل الاسم والدور، ثم بدّل إلى تبويب آخر وارجع. يجب أن يبقى الاسم والدور، وتُمسح كلمة التأكيد، ويظهر التحقق داخل الصفحة مع تعطيل الإجراءات مؤقتًا حتى ينتهي. لا تُستبدل الصفحة كاملة في العودة العادية لجلسة لم تنته. يبقى التحقق الأولي عند فتح التطبيق، وتُزال بيانات الإدارة إذا انتهت الجلسة أو رفضها الخادم أو تعذر الاتصال. أغلق صفحة مدار القديمة وافتح الرابط من جديد بعد النشر لتحميل بناء الواجهة الجديد.

1. تعرض القائمة اسم الحساب ودوره وحالته وعلامة الكلمة المؤقتة. التنقل بصفحات محدودة، ولا تظهر كلمة المرور أو hash أو بيانات الجلسة.
2. لإنشاء حساب: أدخل اسمًا غير مكرر واختر دورًا موجودًا ثم كلمة مرور حسابك الحالي لتأكيد الإجراء. تتولد كلمة مؤقتة عشوائية تعرض مرة واحدة لتسليمها للمستخدم؛ يغيرها عند أول دخول.
3. تغيير الدور وتعطيل الحساب وإعادة تعيين كلمته تتطلب كلمة مرور المنفذ الحالية وتبطل جلسات الحساب المستهدف. التعطيل يحفظ الحساب وسجله؛ لا حذف أو إعادة تنشيط في هذه الدفعة.
4. لا تستطيع تعطيل حسابك أو تغيير دورك بنفسك. يسمح بإعادة تعيين كلمتك إداريًا: تبطل جلساتك وتظهر الكلمة الجديدة مرة واحدة في شاشة معزولة ثم تعود لتسجيل الدخول. احفظها قبل إغلاق العرض؛ تختفي عند إخفاء الصفحة أو التنقل ولا يمكن استرجاعها بقراءة الحساب.
5. عند رسالة تعارض حدث القائمة قبل إعادة الإجراء، وعند انقطاع الشبكة تحقق من حالة الحساب قبل أي محاولة أخرى. لا تدعي الواجهة نتيجة لم تصلها ولا تعيد عمليات الحفظ تلقائيًا.

اختبارات الخدمة وHTTP والمستودع والمتصفح محلية ببيانات اصطناعية منفصلة؛ لا تثبت جميع أقفال TiDB أو أداء Railway. أكد المستخدم الفحوص المحددة للنسخة المنشورة وقبل إدارة المستخدمين صراحة وفق D-062 في WORK_PLAN.md. يبدأ جزء تخصيص المستخدم وفق D-063 وD-064؛ تبقى له تجربة وقبول مستقلان، ولا يعني قبول المستخدمين اكتمال الأساس.

## تجربة تخصيص الصلاحيات — جزء مستقل من M3-02

بعد نشر نسخة هذه الدفعة، افتح `/permissions` أو «تخصيص الصلاحيات» من مساحة العمل. لا متغيرات بيئة أو أوامر SQL أو bootstrap جديدة. الدوران ومنحهما للعرض فقط؛ التخصيصات مستقلة لكل مستخدم.

1. ادخل بمدير مخول واختر حسابك: تظهر الصلاحيات للمراجعة، ويمنع تعديل تخصيصات الحساب نفسه. يتولاها مدير آخر مخول.
2. اختر حسابًا آخر وراجع منح دوره والنتيجة المحفوظة. حدد المطلوب من «حسب الدور» أو «سماح خاص» أو «منع خاص». النتيجة المعروضة تخص الحفظ السابق حتى ينجح الحفظ الجديد.
3. أدخل كلمة مرور **حساب المدير المنفذ** الظاهر في «حساب تأكيد الإجراء»، ثم احفظ. عند تغير فعلي تنتهي جلسات الحساب المختار، ويطبق القرار عند دخوله مجددًا. لا تتغير كلمة مروره أو حالته أو دوره.
4. لإزالة تخصيص، اختر «حسب الدور» واحفظ. الحفظ المطابق للحالة الحالية لا يبطل الجلسات. عند تعارض أو نتيجة حفظ غير مؤكدة، أعد تحميل الصلاحيات وراجعها قبل محاولة أخرى.
5. تحقق بحساب الموارد البشرية دون منح خاص: رابط `/permissions` والطلبات المباشرة ممنوعة. جرّب تبديل اللغة وعرض الجوال. عند تبديل التبويب تبقى اختيارات المسودة وتُمسح كلمة التأكيد وتتعطل الإجراءات خلال فحص الجلسة الخلفي.

تغييرات صلاحيات الحسابات الفعلية ينفذها المستخدم وفق حاجته؛ اختبارات المساعد محلية بحسابات اصطناعية دون تغيير حسابات المنشأة. يسجل القبول والملاحظات لهذا الجزء في WORK_PLAN.md قبل بدء الجزء التالي. قياس TiDB والأقفال الفعلية وتثبيت PWA على أجهزة فعلية اختبارات مستقلة؛ لا تثبتها الذاكرة البديلة أو تصغير نافذة المتصفح.
