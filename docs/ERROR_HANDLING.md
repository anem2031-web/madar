# معالجة الأخطاء والسجل الفني — M3-05

نطاق قبل البرمجة في 2026-11-24 وفق D-076 وC-143 في [الخطة](../WORK_PLAN.md). يراجع مع [مركز التدقيق](AUDIT_CENTER.md) محليًا قبل النشر، دون افتراض قبولهما. يعتمد قسم معالجة الأخطاء في [تصميم الأمان](SECURITY_AND_AUDIT_DESIGN.md) والمتطلبات التقنية. لا قاعدة أو اعتماد أو صفحة جديدة.

## النطاق والمسؤوليات

- `server/core/errors/`: مرجع طلب UUID يولده الخادم قبل تحليل الجسم ولا يثق بمرجع يرسله العميل، وعقد رد عام وتحقق من الرموز الآمنة، وتصنيف أخطاء النقل والتحليل، وسجل فني محدود الحقول. تربط به Express وtRPC ومحولات الوحدات القائمة وعامل التدقيق وأخطاء التشغيل ذات الصلة.
- `shared/errors/`: عقد وأكواد أو مفاتيح رسائل عامة آمنة. تبقى رموز المجال والتفاصيل المترجمة الحالية متوافقة؛ لا تحول رفض تأكيد كلمة المرور إلى انتهاء جلسة، أو رفض إجراء إلى منع الصفحة.
- `client/src/lib/` ومكوّن feedback مشترك: استخراج رمز مسموح ومعرف UUID فقط، وعرض الرسالة المترجمة والمرجع دون message أو stack خامين. تدمجه شاشات الدخول والمستخدمين والتخصيصات والفروع والترقيم والتدقيق والحارس. لا يختلق مرجعًا عند انقطاع الرد.
- تبقى خدمات الوحدات مسؤولة عن أخطاء الأعمال المعروفة. لا تغيير لحسابات أو صلاحيات أو مدد الجلسات أو الحظر أو معاملة التدقيق. لا صفحات جديدة؛ صلاحيات الصفحات الحالية ونطاقها وحارس الخادم باقية. لا تسلسل أو فهرس أو استعلام قاعدة جديد لهذا المركز.

## سلوك الرد والسجل

كل فشل HTTP أو tRPC قابل للتتبع يعيد رمزًا ومفتاح رسالة آمنين وrequestId مع ترويسة X-Request-ID المتوافقة، مع no-store. يحافظ الرد على معاني HTTP الحالية، ويميز JSON غير صالح وحجمًا أكبر من المسموح عن عطل الخادم. لا SQL أو تفاصيل اتصال أو استثناءات خام أو Cookie أو كلمات مرور أو رموز في الرد أو السجل. مرجع الطلب نفسه يربط حدث التدقيق الموجود بالخطأ الفني؛ السجل الفني ليس بديلًا عن outbox.

يسجل الخادم وقتًا ومرجعًا وموقعًا وتصنيفًا تقنيًا من قوائم مسموحة، دون جسم الطلب أو URL أو قيمه أو stack أو نص خطأ المشغل. يمكن تصنيف أخطاء اتصال أو مهلة أو تعارض معاملة من رموز مشغل معروفة فقط، مع اجتياز محدود وآمن للأسباب. يمنع التسجيل المكرر لنفس الفشل في محول الوحدة والمنسق، وفشل مخرج التسجيل لا يسبب حلقة أو يغير نتيجة العمل. سجل التشغيل في مخرجات الخادم ضمن وصول مشغلي البيئة، ولا يوجد API لقراءته. لا ادعاء بتشفير أو فحص أدوار Railway أو سياسة حفظ غير متحقق منها، ولا خدمة تسجيل خارجية.

## الواجهة والتعافي

تحفظ الواجهة رسائل كل وحدة وتميز الرفض المعروف عن انقطاع النقل ونتيجة كتابة غير محسومة. لا تعيد عملية كتابة تلقائيًا. تبقى حواجز المراجعة القائمة وتضاف لإدارة المستخدمين عند النتيجة غير المحسومة أو فشل تحديث القائمة بعد حفظ مؤكد، مع تحديث يدوي ناجح قبل كتابة لاحقة. تعرض حالة الحفظ المؤكد منفصلة عن تعذر التحديث، وتحافظ على عرض الكلمة المؤقتة مرة واحدة ومسار إعادة التعيين الذاتي وإبطال الجلسة. لا تجرى إعادة تعيين أو كتابة فعلية لاختبار هذه الحالات على حسابات المنشأة.

تترجم تسمية مرجع الطلب بالعربية والإنجليزية ويعرض UUID باتجاه LTR داخل السياق مع التفاف يمنع تمدد الجوال. تختفي المراجع القديمة مع زوال الخطأ أو بدء طلب جديد، ولا تنقلها النتائج القديمة بين المستخدمين أو الطلبات. خطأ تحقق محلي أو انقطاع دون رد لا يختلق مرجع خادم. خطأ نشاط الشبكة لا يصف نفسه بانتهاء الجلسة المثبت؛ يظل مسح البيانات المحمية عند تعذر التحقق قائمًا.

## التحقق وحدود التسليم

اختبارات ذات معنى: رموز وحالات HTTP القائمة، وJSON وحجم الطلب قبل المصادقة، والتحقق العام والمسار المجهول، وتزوير مرجع العميل أو رمز fault وقت التشغيل، وترابط الترويسة والرد والتدقيق، وغياب أسرار محقونة عن الرد والسجل، وفشل مخرج السجل وعدم التكرار، وخطأ عامل التدقيق دون تسجيل محتواه أو إعادة الأعمال. اختبارات واجهة لاستخراج المرجع ومنع الأكواد الخام، وRTL/LTR والتجاوب، والتمييز بين رفض وحفظ غير محسوم وحفظ مؤكد ثم فشل التحديث، وعدم إعادة إرسال الكتابة.

يلزم TypeScript وVitest والبناء وNode24 ومراجعة المصدر والمتصفح ببيانات ذاكرة منفصلة. لا حقن فشل أو تعديل في إنتاج madar ولا تشغيل عامل اختبار عليه. لا نشر في هذه الدفعة؛ تراجع مع M3-04 محليًا وفق D-076، ثم توثق خطوات النشر وفحوص البيئة والقبول لاحقًا. اختبارات أداء وتزامن TiDB والأجهزة الفعلية وفصل حساب القاعدة تبقى بشروطها السابقة دون موعد مخترع.
