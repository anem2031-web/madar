# مركز التدقيق — دفعة M3-04

متابعةM3-07/C-197: انتظارTiDB المذكور في سجلات التصميم أدناه تاريخي؛ نُفذ C-186/C-189 ثم C-194 علىmadartest، وطوبقت كل أحداث الجولةالأخيرة90/90 مع نقل عاملين دون فقد/تكرار، وجرد وتنظيف كاملين. لا يساوي ذلك جردأحداثالإنتاج أو تحققكل معاملات الوحدات. قبولالمركزD-077 محفوظ؛ [مصفوفةالتحقق والمعلقات](FOUNDATION_VERIFICATION.md) هي مرجع المتابعة الحالية.

تكامل D-080/C-165: أحداث الأعمال الأصلية للأربع عمليات التنظيمية تضافمرةواحدة معoperationId، وإعادة نتيجة الإيصال لها actionالأصلي متبوعًا بـ.replay وmetadata.replayed:true دونbefore/after جديدين أو تغيير أعمال ثانٍ. أضيفUUID وboolean بصرامة إلىالحقول المسموحة، وإلى إسقاط تفاصيل الخادم والعقد وعرض الواجهة والترجمتين؛ يظهر المعرفLTR ويلتف دون توسيع الجوال. لا يُعرضreservation_token أوinput_hash أو قيم سرية، ولاتغيير لجداولالتدقيق أوصلاحيةaudit.read أوسياسةoutbox. التفاصيل والاختبارات في[تصميم حماية الإعادة](WRITE_REPLAY_FIX_PROPOSAL.md)، دون ادعاء تحقق نقلأحداث الإنتاج أو أقفالTiDB من المخزن المعزول.

حُدد النطاق قبل البرمجة في 2026-11-24 وفق D-075 وC-141 في [الخطة](../WORK_PLAN.md)، بعد قبول إدارة الترقيم D-074. تعتمد الدفعة [سياسة الأمان والتدقيق](SECURITY_AND_AUDIT_DESIGN.md) و[السيكما](DATABASE_SCHEMA.md) و[الاستعلامات](DATABASE_QUERIES_AND_PERFORMANCE.md). حالة التسليم والقبول ونتائج التحقق النهائية في الخطة؛ نجاح الاختبارات لا يعني قبول المستخدم أو نشر الإصدار.

## النطاق ومعايير القبول

- عامل داخلي في Node ينقل أحداث audit_outbox إلى audit_events، مع حفظ الأصل وحالة المحاولة واسترداد الحجز المنتهي. لا يعيد أعمال المستخدم ولا يصدر حدثًا عن النقل نفسه.
- صفحة `/audit` مسجلة بالحارس المركزي تحت `audit.read` وترتيب 50، بعد الصفحات الحالية. النطاق جميع أحداث المنشأة للمخول؛ لا تجاوز تلقائي لمدير النظام. الموارد البشرية ممنوعة افتراضيًا، والتخصيص الخاص يطبق السياسة الحالية.
- قراءة صفحات من 25 حدثًا بترتيب occurred_at ثم event_id تنازليًا، ضمن فترة إلزامية لا تزيد على 31 يومًا. البداية آخر 7 أيام؛ التحديث اليدوي للفترة الافتراضية يحركها حتى الوقت الحالي ويرجع للصفحة الأولى مع حفظ المرشحات. الفترة المخصصة تبقى ثابتة عند التحديث.
- التصفية بالوحدة والنتيجة ومعرف المستخدم، والبحث بمعرف الحدث لفتح تفاصيله ولو خارج الفترة. لا بحث نصي داخل JSON أو عدد إجمالي لسجل التاريخ أو OFFSET. مرشحا الوحدة والنتيجة يطبقان بعد نطاق الوقت، وليسا مغطَّيين بفهرس مستقل.
- التفاصيل الآمنة تعرض هوية المنفذ التقنية ودوره وقت الإجراء والمرجع ونسخته والنتيجة والسبب والقيم المسموحة قبل وبعد. لا تُنسب أسماء حالية إلى هوية تاريخية، ولا يعرض JSON خام أو تفاصيل تقنية أو أسرار. الوقت يعرض بتوقيت الرياض في اللغتين.
- حالة التسليم: أعداد pending وleased وfailed عبر بادئة الحالة في الفهارس القائمة، وأقدم حدث معلق وعينة من عشرة أخطاء دائمة ومعرفاتها وأسباب مفهومة. لا تعرض محتوى الأحداث غير الآمن. لا polling يولد أحداث قراءة بلا نهاية.
- كل طلب قائمة أو تصفية أو تفاصيل يسجل حدثًا واحدًا في outbox بعد التحقق وقبل إعادة البيانات، في معاملته نفسها؛ لا حدث لكل صف. تعذر حفظ هذا الحدث يمنع الرد المحمي. الرفض يسجل وفق الحارس الحالي. لا أرقام تسلسلية لهذه الدفعة؛ تستخدم UUID القائمة.
- العربية والإنجليزية وRTL/LTR والجوال ضمن التخطيط الحالي، دون تقديم سايدبار M3-06. تضاف الصفحة إلى قائمة تنقل PWA فقط؛ لا تخزن بياناتها أو API محليًا.

لا تعديل أو حذف أو تصدير أو محو آلي، ولا زر تشغيل أو إعادة محاولة من الواجهة. `audit.read` صلاحية قراءة. لا جداول أو حقول أو فهارس أو ترحيلات أو متغيرات بيئة أو اعتمادات جديدة.

## المسؤوليات والعقود

`server/core/audit/`: التحقق من المصدر، ومقارنة الحدث الكامل، ومستودع النقل والحجز والعامل، ومستودع القراءة والخدمة والتحقق والمسارات واختباراتها. `shared/audit/`: عقود قراءة آمنة فقط. `client/src/modules/audit/`: الشاشة والمرشحات والتفاصيل وحالة الطلب، وترجماتها في shared/i18n. الاتصال والمعاملات عبر المركز القائم، والمصادقة عبر authorizeInTransaction؛ لا محرك صلاحيات ثانٍ.

تتحقق قائمة حقول مسموحة وأحجام وأنواع محدودة قبل كتابة المصدر، بحد 16 KiB للحدث محسوبًا ببايتات UTF-8. القيم الشخصية غير المعتمدة وكلمات المرور والرموز لا تمر. المصدر التاريخي غير المطابق لا يُغير أو يُنقل بصمت؛ يبقى محفوظًا وتظهر مشكلة مفهومة للمخول. حقلا الاستعادة التاريخيان source وrevokedSessions يحفظان في النسخ والمقارنة، ويستبعدان من DTO العرض. تحفظ قيم null وfalse و0 دون الخلط بينها وبين غياب الحقل.

المقارنة عند وجود event_id تستخدم كامل المحتوى الأصلي، مع ترتيب مفاتيح JSON وتوحيد NULL وتاريخ UTC بالميلي ثانية، وحفظ ترتيب المصفوفات. لا تقارن الإسقاط المعروض فقط. تعارض المحتوى لا يكتب فوق السجل، ولا تعتمد صلاحية رمز تاريخي على بقائه في كتالوج الصلاحيات الحالي.

الحجز CAS للحالة pending ووقت الاستحقاق، مع lease_token مستقل وزيادة عدد المحاولات. تسليم كل حدث بمعاملة قصيرة: قفل المصدر، وفحص الملكية والمهلة بوقت القاعدة الحالي بعد القفل، ثم إدراج نسخة إن غابت أو مقارنة الموجودة، ثم تأكيد التسليم في المعاملة نفسها. فشل التأكيد يلغي الإدراج. يسترد العامل leased المنتهي بتحديث مشروط؛ العامل القديم لا يؤكد حجزًا أحدث. فقد الرد بعد التثبيت يحل بإعادة القراءة ولا يعيد أعمال المستخدم.

حدود تشغيل فنية أولية وليست SLA مقاسة: دفعة 25، ومعالجة متسلسلة بحجز كل حدث عند دوره، ومهلة 30 ثانية، ودورة كل 5 ثوان بعد انتهاء السابقة، وتراجع تلقائي للفشل المؤقت حتى 60 ثانية دون إسقاط أحداث بسبب طول العطل. فشل التحقق أو التطابق دائم ظاهر دون حذف. يتوقف العامل وينتظر العملية الجارية قبل إغلاق اتصال القاعدة. يبدأ صراحة في التشغيل connected بعد الاستماع؛ لا يبدأ عند استيراد مكتبة أو داخل اختبارات createApp.

## الفهارس والقياس

المسارات DBQ-17..21 تستعمل ix_audit_outbox_delivery وix_audit_outbox_lease والمفتاحين الأساسيين، وix_audit_events_time وix_audit_events_actor. تاريخ المورد المرتب بالنسخ DBQ-22 ليس شاشة مستقلة في هذه الدفعة؛ تعرض النسخة دون ادعاء ترتيب عالمي لتغييرات موارد مختلفة. لا تغيير فهرس بلا دليل.

هدف قراءة فترة من 10,000 حدث اختبار هو p95≤1.5 ثانية. يلزم قياس زمن وسرعة تصريف المتراكم قبل اعتماد SLA. لا يجوز ادعاء تحقيقهما بمخططات جداول فارغة أو بديل الذاكرة. يبدآن في بيئة اختبار منفصلة مصرح بها، دون موعد متفق عليه.

## التحقق والاستعادة

التحقق يشمل الصلاحيات والرابط المباشر والمنع والمنح والتعطل الآمن، والتصفية والصفحات المتساوية الوقت وإبطال النتائج القديمة، ومنع الأسرار والأنواع غير المعروفة، وحدثًا واحدًا لكل قراءة دون حلقات نقل، والحجز المتنافس وفشل الإدراج والتأكيد والتراجع واسترداد الحجز القديم، والتكرار المطابق والمختلف والتراجع المؤقت. تشمل الفحوص TypeScript وVitest والبناء وNode24 ومتصفحًا معزولًا باللغتين والجوال. اختبارات الذاكرة وSQL المسجل لا تثبت أقفال TiDB أو حقن الفشل الفعلي؛ لا نشغل عامل اختبار على الإنتاج أو ننشئ فيه سجلات أعمال وهمية. حدود حساب root المؤجلة D-055 تبقى صريحة.

عند تعطل النقل مؤقتًا تبقى الأحداث في المصدر وتستأنف المحاولات تلقائيًا. عند failed لا يحذف العامل الأصل أو يغيره؛ يراجع المشغل السبب الآمن ومعرف الحدث. الحدث غير المطابق يحتاج مراجعة المنتج والتوافق التاريخي؛ وتعارض نسختين يحتاج مقارنة المحتوى الكامل وتحديد السبب، دون تجاوز التحقق أو الكتابة فوق التاريخ. بعد إصلاح موثق ومصرح به، تكون إعادة المعالجة إجراءً تشغيليًا محددًا يعيد بيانات التسليم فقط للحالة pending بمقارنة الحالة المتوقعة؛ لا إعادة ضبط جماعية أو تعديل للمحتوى أو بيانات الأعمال. لم تُنفذ إعادة معالجة فعلية بهذه الدفعة.

التراجع البرمجي إلى الإصدار السابق يوقف العامل ويبقي المصدر والأحداث المنقولة وسجل الترحيلات دون حذف. تظل عمليات الإصدار السابق تحفظ المصدر وفق سلوكها. لا ترحيل عكسي مطلوب لأنه لم يتغير المخطط، ولا يكرر النقل أعمال المنشأة.

## سجل القراءة الفنية على madar

في 2026-11-24 كان العدد 181 في outbox و0 في audit_events وقت الفحص. فُحصت أسماء وأنواع مفاتيح JSON دون عرض قيمها، ثم اجتاز المحتوى الآمن لجميع الأحداث الـ181 التحقق المركزي دون تعديل. نجح مستودع القراءة وقراءة وقت القاعدة الفعلي. لم يشغل العامل أو يكتب حدثًا أو يطالب بحجز على قاعدة المنشأة أثناء التطوير.

أظهر EXPLAIN فهارس النقل والحجز والزمن والمنفذ القائمة. الإسقاط الكامل للشاشة يستعمل IndexLookUp، والمرشحات الإضافية تستعمل Selection، والأعداد تستعمل StreamAgg؛ التفاصيل في وثيقة الاستعلامات. جميع الخطط stats:pseudo؛ لا قياس p95 أو بيانات ممثلة أو تزامن فعلي من هذه القراءة.

## نتيجة التسليم المحلي — C-142

نجح 198 اختبارًا في 32 ملفًا، وفحص TypeScript والبناء من 87 وحدة واستيراد الوحدات وتشغيل الحزمة في Node24. شملت تجربة المتصفح المعزولة الصفحات والتصفية والتفاصيل والقيم الفارغة والخصوصية والصلاحيات والتعطل والتعافي والتحديث المتحرك والفترة المخصصة واللغتين وعرض 320px. عولج تجاهل قيم التاريخ المحلية عند الإرسال بالاعتماد على FormData الفعلية، وأعيد اختبار الفترة المخصصة وثباتها وحد 31 يومًا.

أغلقت التبويبات المؤقتة وأوقفت خوادم 4336 و4337 وحذفت ملفات التجربة. بقي ترحيل 0000 ببصمته الأصلية، ولا تغيير للمخطط أو CHECK أو إعداد الاتصال. اجتاز فحص الفروق والروابط المحلية دون مراجع مفقودة. الدفعة جاهزة محليًا وتنتظر نشر المستخدم وفحص المساعد وقبول المستخدم؛ لا نتيجة أداء أو تزامن TiDB أو تثبيت جهاز فعلي مدعاة.

## فحص النقل المنشور — C-145

نجحت القائمة والتفاصيل والتصفية وصفحتان من25حدثًا بلا تكرار في متصفح ADMIN. ظهرت حالة النقل55معلقًا و1قيد المعالجة و0فاشل، ثم0/0/0 في قراءة لاحقة. أكدت لقطة SELECT-only مستقلة في madar أن188من188مصدرًا مسلَّمة وأن المركز188، وبالمقارنة الكاملة لكل188حدثًا ضمن حد1000:188مطابقة،0مفقودة،0مختلفة،0غير صالحة. لم تطبع القيم أو المعرفات أو الأسرار، وأغلق الاتصال. اللقطة قبل قراءات إضافية؛ لا تفترض العدد الحالي ثابتًا.

استعمل الفحص معاملة المركز القائمة مع SELECT فقط دون FOR UPDATE أو تشغيل العامل أو كتابة DML/DDL. فشلت محاولتا إعداد بخيارات read-only قبل قراءة البيانات؛ لا اعتماد لعلم READ ONLY مفروض من القاعدة أو إعداد عام تغير. هذه سلامة حالة مرصودة، وليست تجربة تنافس عاملين أو استرداد عطل متعمد أو p95. بقي فحص kamal والقبول، ولا تستنتج تجربة منع من ظهور لوحة ADMIN.
