# إعادة اختبارات TiDB — C-188/C-189

أعاد المستخدم طلب الفحوص على `madartest` بتاريخ2026-11-25 بتوقيت الرياض. نُفذت جولة مستقلة وحفظت في [نتائج الإعادة](TIDB_RETEST_RESULTS.json)، مع إبقاء [نتائج الجولة الأولى](TIDB_TEST_RESULTS.json) دون استبدالها. **تكررت النتيجة: سلامة المعاملات ناجحة، وسعة مجمع تشغيل التطبيق عند عشرة طلبات فاشلة.**

## ما أعيد بالفعل

- جرد TLS واسم القاعدة ومطابقة الترحيلين:16 جدول تطبيق و42 مفتاحًا وفهرسًا و13 علاقة، وجميع صفوف التطبيق صفر قبل البدء. لم تُنفذ DDL أو ترحيلات أو تعديلات CHECK في هذه الجولة.
- نفس حالات السلامة الأساسية الاثنتي عشرة الموضحة في [تقرير الجولة الأولى](TIDB_VERIFICATION.md): عشرة متسابقين على إيصال واحد، تسع إعادات مع تدقيق صحيح، إضافات مستقلة، تعارض نسخة واضح، منع HR، رفض اختلاف المدخل، تراجع الأعمال والإيصال والتدقيق عند الفشل ثم نجاح الإعادة، وفقد رد HTTP ملتزم ثم إعادة صريحة بلا تكرار. شُغل خادم HTTP محلي حقيقي على4355 واتصل بقاعدة TiDB الفعلية.
- بذور عشرة حسابات وجلسات و200 موظف اصطناعي. هذه المرة أُخذت منح الدور من كتالوج المشروع، وحسابات التجربة وجلساتها منفصلة كليًا عن الإنتاج. تهيئة الجلسة مباشرة لا تعني اختبار شاشة الدخول.
- عاملان فعليان للتدقيق:40 حدثًا منقولًا دون ازدواج مع تطابق المعرف والوقت والإجراء والنتيجة. نجحت30 قراءة، كل منها26 صفًا من10,040 حدثًا، عبر عشرة اتصالات مستقلة. بيانات الوقت موزعة اصطناعيًا داخل فترة محددة؛ لا تعتبر المقارنة الزمنية تجربة أداء مضبوطة تمامًا بين الجولتين.
- EXPLAIN لمفاتيح الإيصالات والأقسام والموظفين والتدقيق. الخطط الخام المنقحة محفوظة؛ لم يشغّل ANALYZE ولم يعدل فهرس أو مخطط.
- مجمع تشغيل واحد من `openDatabase` دون تعديل إعداداته، وعشر جلسات لمستخدمين مختلفين: تجربة خمسة ثم عشرة طلبات HTTP، ومسبار حجز خمسة اتصالات ورفض السادس ثم التعافي بعد تحريرها.

## التنظيف وحالة الخطة

أثبت الجرد النهائي صفر صف في جداول التطبيق الستة عشر، مع تطابق بصمتي وتوقيتي الترحيلين وبقاء42 مفتاحًا وفهرسًا و13 علاقة. نُظفت صفوف الجولات بمعرفاتها الاصطناعية، وأغلقت الاتصالات وخادم4355، وحذفت الملفات المؤقتة وملف بيئة الاختبار المستبعد من Git بعد حفظ التقرير. لم تستخدم قاعدة`madar` أو أسرارها، ولم تتغير ملفات المنتج أو الحزم أو المخطط أو النشر. لم تعد Vitest أو بناء المنتج لأن كوده لم يتغير.

اختبار Android وiPhone يبقى مؤجلًا بقرارD-084. لم تكتمل M3-06 بسبب BUG-DB-01 المتكرر، ولا يبدأ الجزء التالي أو الموظفون من هذه الإعادة. لا تعاد الفحوص نفسها دون تغيير ذي صلة أو توجيه جديد من المستخدم.
