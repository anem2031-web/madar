# فحوص PWA — دفعة M3-06

## النطاق قبل التنفيذ — C-161

طلب المستخدم «التالي» بعد اكتمال فحص الغلاف المنشور بالحسابين وقبول التصميم D-079. تبدأ هنا فحوص PWA-01 إلى PWA-05 القائمة في تصميم التشغيل؛ لا تغيير لسلوك التحديث أو إضافة تنبيهات أو طابور كتابة أو اعتماد جديد من هذا الطلب.

- مراجعة العامل وتسجيله والبيان والأيقونات وصفحة الانقطاع وسياسة تخزين البيانات، وتشغيل اختبارات PWA القائمة.
- فحص أصول PWA المنشورة وMIME والكاش، دون إعادة فحوص الغلاف أو كتابة بيانات إنتاج أو تغيير الحسابات والجلسات لأجل تجاوز عائق.
- فحص المتصفح المتاح للتسجيل والتحكم والمسارات العميقة والانقطاع والعودة والخصوصية. تُستخدم بيئة محلية مؤقتة ببيانات اصطناعية عند الحاجة لتعطيل الاتصال أو اختبار حفظ وتحديث؛ لا تعطيل لخدمة الإنتاج أو استبدال عاملها يدويًا.
- اختبار دورة عاملين محليين منفصلين عن أصل الإنتاج إذا سمحت أدوات المتصفح، مع توثيق طريقة التحفيز وحدود الاختبار. لا يساوي اختبار انتظار العامل تنفيذ واجهة «تحديث الآن» أو التنسيق بين التبويبات إذا لم يكونا مبنيين.
- لا تثبيت أو تغيير إعدادات جهاز المستخدم أو مسح مخابئه أو قراءة cookies أو أسرار أو كلمات مرور. تُفحص بنية التخزين فقط بوسيلة قراءة متاحة، وتُحجب القيم السرية. إذا تطلب الاختبار دخولًا حقيقيًا خاصًا، تطبق D-070.
- لا جداول أو API أعمال أو استعلامات أو فهارس أو صلاحيات أو نطاق بيانات أو أرقام جديدة؛ هي دفعة تحقق للأساس الحالي. لا أثر على القاعدة أو CHECK أو env أو حزم المشروع.

## نتائج المصدر والاختبارات القائمة

نجح 11 اختبارًا في server/pwa.test.ts و8 في server/app.test.ts، في تشغيلين دون تغيير ملفات التطبيق أو بناء جديد. ثبت في الاختبار المعزول تخزين صفحة الانقطاع العامة وحدها، وتطابق المسارات الستة مع سجل الصفحات، وتجاوز API والكتابة والأصول والمسارات المجهولة والخارجية، وحفظ رد503 الفعلي بدل تحويله إلى انقطاع. لا يثبت هذا وحده دورة عامل فعلية أو cache حقيقيًا أو تثبيتًا.

التنفيذ الحالي ينتظر انتهاء استخدام العامل القديم؛ لا skipWaiting أو clients.claim أو إشعار «تحديث الآن» أو إعادة تحميل تلقائية. الإشعار والتنسيق الموصوفان في وثيقة التصميم مقترحان غير مبنيين، ولا يُنفذان من دفعة الفحص دون تثبيت نطاقهما. بعد أول تسجيل قد لا تتحكم النسخة بالصفحة الحالية حتى تحميل لاحق. صفحة الانقطاع تعرض العربية والإنجليزية معًا وزرها يعود إلى/؛ إعادة تحميل المسار العميق تختلف عن الضغط على هذا الزر.

## تحقق إضافي قبل اعتماد نتيجة انقطاع الكتابة

رصد الاختبار المحلي لضغطة حفظ واحدة أثناء تدميرsocket محاولتيPOST دون أي تغيير ملتزم؛ وبعد الاستعادة لم يزد العدد. لم تكشف مراجعة NameForm وOrganizationScreen وuseOrganization وhttpLink إعادة إرسال صريحة، ولا يثبت ذلك أن طبقة النقل لا تعيد الطلب. السبب غير محسوم من المصدر، فلا ينسب إلى المتصفح أو tRPC افتراضًا. يتبع ذلك اختبار اصطناعي محدود يفقد أول رد ناجح بعد تنفيذ الحفظ، ثم يقيس عدد التغييرات الملتزمة؛ لا حقن فشل أو كتابة إنتاج، ولا تعديل تطبيق من هذا الاختبار.

## نتائج المتصفح المعزول على 127.0.0.1:4348

استخدم الاختبار الحزمة الحالية مع createApp ومخزن التنظيم والمصادقة في الذاكرة وحسابي QAADMIN وQAHR، دون.env أو اتصال قاعدة. صفحة QA ظاهرة ومستقلة في مجلد مؤقت، تعرض حالة العامل وأسماء المخازن ومساراتها والعدادات فقط، ولا تقرأcookies أو قيم تخزين. تعذر قراءةnavigator من نطاقevaluate المعزول في أداة المتصفح، لذلك لم تُحسب تلك المحاولة فحصًا للعامل؛ التشخيص التالي صادر من لوحةQA الفعلية داخل الصفحة.

### التسجيل والانقطاع والعودة

- أظهر التسجيل اليدوي أولًا انتقال العامل إلىactivated وتخزينoffline.html فقط، معcontroller:null للصفحة الأولى. نُظف التسجيل والمخزن، ثم فتح التطبيق نفسه دون زر تسجيل؛ ظهر تسجيلactivated وupdateViaCache:none وكاش الصفحة العامة مجددًا. بعد تحميل لاحق أصبحت صفحةQA متحكمًا بها. هذا يفصل التسجيل عن التحكم.
- أعاد auth.session المحلي200 وapplication/json وno-store، دون عرض جسمه. بعد إسقاط اتصالات التطبيق وAPI اصطناعيًا أعاد فحصAPI فشل شبكة بدلHTML. كانnavigator.onLine ما زالtrue؛ التحفيز تعذر اتصال الخادم المحلي وليس وضع طيران للجهاز.
- محاولة حفظ الفرع أثناء الانقطاع عرضت رسالة نتيجة غير محسومة وحاجز مراجعة وعطلت الكتابة. رُصدت محاولتاPOST ساقطتان وصفر تغييرات ملتزمة؛ بعد استعادة الاتصال والتحميل بقي العدد2 وصفر تغييرات. لا طابور كتابة أو حفظ مؤجل رُصد، ولا يجوز وصف كل ضغطة بأنها طلبHTTP واحد.
- أعاد تحميل/organization تحت التحكم أثناء إسقاط الاتصال صفحة الانقطاع العامة بالعربية والإنجليزية بلا حساب أو بيانات. احتفظ العنوان بالمسار؛ وبعد استعادة الاتصال وإعادة التحميل عاد التنظيم والمصادقة. زر صفحة الانقطاع نفسه يعود إلى/ كما في المصدر، ولم يُدّع أنه يعيد المسار العميق.

### دورة العامل والمسودة والحفظ

- نسخةA هي العامل الحالي دون تغيير. المرشحانB وC غيرا اسم الكاش فيfixture فقط، بينما حزمةReact ثابتة؛ لا ادعاء اختبار إصدارَي تطبيق منشورين. فشل جلبoffline.html للمرشحC بـ503 جعلC redundant وأبقىA نشطًا والمسودة كما هي. خلّفC كاشًا فارغًا مؤقتًا دون بيانات.
- ثبتB فيwaiting مع بقاءA متحكمًا وتبويبي التطبيق وQA مفتوحين؛ بقيت مسودة الفرع. عُلّقPOST أعمال واحد، وظهرت «جارٍ الحفظ» معwaiting كما هي، ثم أُفرج عنه مرة واحدة ونجح حفظ فرع اصطناعي واحد دون انقطاع. العداد ارتفع من2 إلى3 محاولات إجمالية ومن0 إلى1 تغيير ملتزم؛ لم تنته مهلة التعليق.
- بعد خروج الحساب الاصطناعي وإغلاق تبويب التطبيق، ظلB ينتظر تبويبQA المتحكم. بعد إغلاق كل تبويبات الأصل وفتحQA مجددًا صارactive دونwaiting، ولم يبق إلا كاشB وفيهoffline.html وحدها؛ نظفactivate كاشَيA وC. لا إعادة تحميل تلقائية أو زر تحديث مطبق أو مقاس لعدد إعادة تحميل من هذا المسار؛ التفعيل حصل بعد الإغلاق.

### الخصوصية بين الحسابين

بعد خروجQAADMIN والرجوع بالتاريخ ظهرت شاشة الدخول دون الإطار الخاص أو اسمQAADMIN. عند دخولQAHR ظهر اسمه ودوره وروابط/ و/organization فقط، دون مجموعة الإدارة أو نص الحساب السابق. ظلlocalStorage يحويmadar.language فقط، وsessionStorage وIndexedDB فارغين؛ الكاش لم يتضمنAPI أو حسابات. هذا فحص تخزين وDOM معزول، لا تفتيش heap شاملًا أو إثبات كل سياسات متصفح وجهاز فعلي. خرجQAHR قبل التنظيف.

## نتيجة اختبار فقد الرد بعد الحفظ — BUG-PWA-01

أعيد تشغيل مخزن ذاكرة نظيف على الأصل المحلي نفسه. بعد دخولQAADMIN ضُغط حفظ إضافة فرع مرة واحدة. لف الاختبار write/end/flushHeaders للرد المرشح فقط؛ انتظر نجاح200 وحدث تدقيق ملتزم لنفسrequestId، ثم أسقط الرد مرة واحدة قبل إرسال بايتات النجاح. لم ينشئ الاختبار أو يعد إرسال أي طلب أعمال.

النتيجة الفعلية: businessPosts=2 وcommittedResponseDrops=1 وcommittedOrganizationWrites=2، وعدد الفروع ارتفع1→3. عرضت القائمة فرعين بالاسم الاصطناعي نفسه مع رسالة إضافة ناجحة واحدة. **فشل شرط منع تكرار تنفيذ الحفظ عند فقد الرد.** لا يصح إغلاق PWA-02 أو اعتماد سلامة الكتابة اعتمادًا على عدم وجود retry صريح في مصدر الواجهة. سبب إعادة الطلب في طبقة النقل غير محسوم هنا؛ قابلية التنفيذ المكرر على الخادم مثبتة لهذا المسار فقط.

بعد الفحص خرج الحساب الاصطناعي وأغلق تبويب17؛ نظف تبويب16 تسجيلات العامل والكاش والتخزين فظهرت جميعها فارغة، ثم أغلق. نُظفت كذلك تجربة التحديث الأولى وتبويبات13/14/15. أوقف الخادم وتحقق إغلاق4348، وحذف.tmp-pwa-verification بعد التحقق من مساره ومحتواه. لم يتغير التطبيق أو حزمته أو القاعدة أو الحسابات أو بيانات المنشأة أو حالة نشره؛ تبويب الإنتاج بقي كما فتحه المستخدم.

أُعد [مقترح إصلاح تكرار الكتابة](WRITE_REPLAY_FIX_PROPOSAL.md) للمراجعة قبل أي تعديل معماري أو جدول أو ترحيل خارج طلب الفحص.

## إصلاح الخلل المصرح به — D-080 وC-165

بعد موافقة المستخدم نُفذت حماية الإعادة للعمليات التنظيمية الأربع محليًا مع إيصال ذري وترحيل إضافي. نجح282اختبارًا والبناء والمتصفح: بعد إسقاط4ردود ملتزمة، وصلت8طلبات بمعرف ثابت لكل زوج، لكن نفذت4تغييرات أعمال فقط و4إعادات نتيجة، مع4إيصالات مكتملة و0ناقصة. نجحت الرسائل باللغتين والحارس والعرض الضيق؛ نُظف أصل التجربة وخادم4351 ومجلده وتبويبات18/19. لا تغييرات إنتاج أو بيانات منشأة أو عاملPWA أو حزم أو env.

أدلة التنفيذ وحدودTiDB في[تصميم الإصلاح ونتائجه](WRITE_REPLAY_FIX_PROPOSAL.md)، وخطوات الترحيل ثم النشر في[دليل الإصدار](WRITE_REPLAY_DEPLOYMENT.md). عولجت الحالة المثبتة محليًا، ولم يثبت نشر الإصلاح أو تطبيق جدوله؛ تبقى الأجهزة والتحديث الكامل ومعاملة القاعدة الفعلية وقبول الإصلاح بشروطها، ولا يغلقM3-06 أو يبدأ الموظفون من هذه النتيجة.
