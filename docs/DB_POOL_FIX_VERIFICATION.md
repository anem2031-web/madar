# إصلاح إدارة الاتصال — BUG-DB-01 / D-085

متابعةD-086: بدأ التحقق الشاملM3-07 بعد توثيق متبقيM3-06 في [سجل المعلقات](FOUNDATION_VERIFICATION.md). تعليمات الانتظار في خاتمة التقرير تصف ترتيب التسليم السابق؛ سمح المستخدم الآن ببدءالتالي دون إسقاط فحصالنشر أو القبول أو الأجهزة المؤجلة. لا يعاد طلب إذن الانتقال.

الحالة: الإصلاح جاهز محليًا للنشر، ونجح التحقق الفعلي على TiDB الاختبار وفق C-194. لا يعد هذا المستند قبولًا لـM3-06 أو إثبات نشر. Android/iPhone مؤجلان صراحة وفق D-084 وتأكيد D-085، إلى إتاحتهما وتوجيه المستخدم، دون موعد متفق عليه.

## التنفيذ

- `server/core/database/acquisition.ts`: بوابة FIFO واحدة؛ حد الاتصالات يشمل الجاري إنشاؤها، وحد مستقل للمنتظرين، ومهلة من بدء الاستعارة تشمل الانتظار وإنشاء الاتصال. يفحص الموعد عند إخراج المنتظر وعند وصول الاتصال حتى إذا تأخر تنفيذ المؤقت. يحذف الطلب المنتهي، ويعيد الاتصال المتأخر دون بدء عمله، ويحتفظ بحساب خانته حتى يعود فعليًا.
- `server/core/database/connection.ts`: تمر query/execute وDrizzle المباشر والمعاملة وping وعامل التدقيق بالبوابة نفسها. يبقى انتظار mysql2 معطلًا لتجنب طابور ثانٍ. لا ينشئ مستودع الوحدة مجمعًا مستقلًا. تملك المعاملة اتصالها من قبل BEGIN حتى نهاية COMMIT/ROLLBACK، ويحرر في finally الخارجية؛ يتلف الاتصال عند خطأ حتى لا يعاد استخدام حالة غير محسومة. الإغلاق يمنع الجديد ويرفض المنتظر ثم ينتظر العمل المقبول والاتصال المتأخر قبل إغلاق المشغل.
- يحتفظ `connection.transaction` و`connection.db.transaction` بالمسار المركزي نفسه. `$client` لا يعرض المجمع الخام، ومحوله يتيح query/execute فقط. لا يستخدم المشروع `iterator()`/البث؛ لا يدعي المحول دعمهما. يجب استخدام الاستعلامات المحدودة والمعاملة المركزية في الوحدات اللاحقة.
- `server/core/errors/database-failure.ts`: تمييز DB_BUSY وDB_WAIT_TIMEOUT وDB_CLOSED في حدود HTTP الستة، بحالة503 ومرجع طلب ورسائل عربية/إنجليزية وسجل منقح. لا تغيير لفحوص كلمة المرور أو الصلاحيات. النتيجة غير المحسومة للكتابة تظل خاضعة للمراجعة وإيصال المحاولة، دون إعادة تلقائية أو ادعاء إلغاء معاملة بدأت.

لا جداول أو ترحيلات أو فهارس أو CHECK أو صلاحيات أو صفحات أعمال أو اعتمادات جديدة. لا متغير تشغيل جديد. فصل حساب اتصال التطبيق ما زال مؤجلًا D-055.

## ضبط السعة والوقت

اختبار الإعداد الأول5اتصالات/10منتظرين/3000ms محفوظ مستقلًا في [نتيجة المحاولة الأولى](DB_POOL_FIX_INITIAL_RESULTS.json). نجح حمل5، وفشل حمل10: القراءة9/10 والحفظ7/10 والإعادة7/10؛ السبب المعلن انتهاء انتظار الاستعارة. نُظفت بيانات الجولة وثبتت سلامة المخطط والترحيلين.

الإعداد الناجح المعتمد للتسليم الفني10اتصالات/10منتظرين/3000ms، ضمن نطاق الإصلاح المعتمد C-193. حد الاتصالات لكل عملية Node، وليس لكل المنشأة أو عدد مستخدميها؛ زيادة نسخ الخادم مستقبلًا تستلزم مراجعة المجموع. هذه القيم ليست معيارًا عالميًا أو تغييرًا لموارد TiDB. مهلة الاتصال الأولي3ثوانٍ وping2ثانية ومهلة العميل15ثانية سياسات مختلفة. مهلة الاستعارة لا توقف معاملة حصلت على اتصالها، ولا تثبت مهلة العميل حصول rollback.

`diagnostics()` متاحة داخليًا وليست API عامًّا: أعداد النشط/المنتظر/الجاري إنشاؤه والرفض والمهلات، ومجموع وأقصى زمن استعارة ناجحة وزمن عمر الاتصال المقبول. لا تحتفظ بمستخدم أو SQL أو مدخلات أو سر. عمر الاتصال يشمل الشبكة والأقفال والعمل؛ لا يساوي وقت CPU في TiDB.
