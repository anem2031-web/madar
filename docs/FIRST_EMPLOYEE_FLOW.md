# متطلبات الأساس وأول مسار للموظفين

## الحالة والغرض

بدأ العمل بتاريخ 2026-11-22 ضمن M1-03 وM1-04. اعتمد المستخدم حقول الموظف الـ14 وإلزاميتها وتفرد الرقم الوظيفي ورقم البصمة، وصلاحيات الأدوار وقاعدة تخصيص المستخدم وحالتي نشط وغير نشط. اكتملت متطلبات المسار الأول على مستوى البيانات والإجراءات الأساسية، مع بقاء التصميم الفني وتنفيذ الوحدة في مهامهما. النطاق العام هو الموظفون والإجازات والموافقات والرواتب؛ لم تُنفذ الوحدة بعد.

المراجع: [خطة العمل](../WORK_PLAN.md)، و[التعليمات](../AGENTS.md)، و[المتطلبات التقنية](TECHNICAL_REQUIREMENTS.md)، و[هيكل المشروع](PROJECT_STRUCTURE.md).

## أسئلة الأساس الجاري حسمها

| المعرف | المطلوب تحديده | الحالة |
| --- | --- | --- |
| B-01 | مستخدمو الإصدار الأول | حُسم: مدير النظام والموارد البشرية فقط؛ لا بوابة دخول للموظفين أو المديرين في نطاق البداية الحالي |
| B-02 | نطاق الفروع | حُسم: جميع الفروع؛ إجراءات ملف الموظف والحقول الـ14 لكلا الدورين موثقة في سياسة الصلاحيات |
| B-03 | حجم البداية | حُسم: 200 موظف وفرع واحد و10 مستخدمين متزامنين؛ يبقى دعم تعدد الفروع معتمدًا |
| B-04 | أولوية المنح والمنع | حُسم: منع المستخدم يتقدم على منح الدور، ومنح المستخدم يتيح غير الممنوح في الدور، وما لم يمنح يمنع؛ لا تجاوز تلقائي لمدير النظام |
| B-05 | حقول ملف الموظف الأول | حُسم: القائمة السابقة مع رقم البصمة ورقم الإقامة ورقم الجواز والجنسية وتاريخ انتهاء الإقامة؛ الإجمالي 14 حقلًا |
| B-06 | الأرقام الوظيفية الحالية أو إصدار أرقام جديدة | حُسم: الاحتفاظ بأرقام الموظفين الحالية؛ لا توليد بديل لها |
| B-07 | أرقام الموظفين الجدد وصيغة الإدخال | يدوي مع منع التكرار بعد إزالة المسافات الطرفية وتجاهل حالة الحروف، وحفظ الأصفار؛ الأطوال مقترحات في قاموس SQL |
| B-08 | إلزامية الحقول | حُسم: الرقم والاسم والفرع والقسم والمسمى وتاريخ المباشرة والحالة إلزامية؛ البقية اختيارية |
| B-09 | تفرد الرقم الوظيفي ورقم البصمة | حُسم: منع تكرار القيمة بين موظفين مختلفين على مستوى المنشأة كلها |
| B-10 | الحالات وقواعد تغييرها | حُسم: نشط وغير نشط مع حفظ الملف والسجل؛ تغيير الحالة له صلاحية مستقلة |
| B-11 | الفرع والقسم | حُسم: الفرع ثم القسم التابع له؛ يمنع قسم من فرع آخر |
| B-12 | إدخال المسمى | حُسم: نص يكتب داخل ملف الموظف؛ لا قائمة مسميات مستقلة |

تُستخدم الإجابات في تصميم البيانات والصلاحيات والفهرسة وحالات الاختبار، ولا تُستبدل بقيم النموذج التجريبي.

## المسار الأول

مستخدم مخوّل يسجل الدخول، ويفتح دليل الموظفين ضمن نطاقه، ويضيف ملف موظف بالبيانات المتفق عليها، ثم يعرضه ويبحث عنه ويعدل البيانات التي يملك صلاحية تعديلها. تُسجل الأحداث المطلوبة وتظهر النتائج باللغة المختارة، مع منع القراءة أو التعديل خارج النطاق حتى عند استخدام رابط أو طلب مباشر.

حساب المستخدم وملف الموظف مفهومان يحتاجان ربطًا متفقًا عليه؛ إضافة موظف لا تعني تلقائيًا إنشاء حساب دخول له. لا تتضمن هذه البداية حذف الموظفين أو إنهاء خدماتهم أو احتساب مستحقاتهم تلقائيًا؛ تُحدد سياسات هذه الإجراءات قبل تنفيذها ضمن مهامها.

## حقول ملف الموظف المعتمدة

| الحقل | الإلزامية | التفرد المعتمد |
| --- | --- | --- |
| الرقم الوظيفي | إلزامي | فريد على مستوى المنشأة؛ تُحفظ الأرقام الحالية |
| اسم الموظف | إلزامي | لا قيد تفرد مطلوب |
| الفرع | إلزامي | لا قيد تفرد مطلوب؛ يختار أولًا |
| القسم | إلزامي | لا قيد تفرد مطلوب؛ تابع للفرع المختار |
| المسمى الوظيفي | إلزامي | نص يكتب في الملف؛ لا قيد تفرد مطلوب |
| تاريخ المباشرة | إلزامي | لا قيد تفرد مطلوب |
| الحالة الوظيفية | إلزامي | لا قيد تفرد مطلوب |
| الجوال | اختياري | لم يطلب المستخدم تفرده |
| البريد الإلكتروني | اختياري | لم يطلب المستخدم تفرده |
| رقم البصمة | اختياري | فريد على مستوى المنشأة عند إدخال قيمة |
| رقم الإقامة | اختياري | لم يطلب المستخدم تفرده |
| رقم الجواز | اختياري | لم يطلب المستخدم تفرده |
| الجنسية | اختياري | لا قيد تفرد مطلوب |
| تاريخ انتهاء الإقامة | اختياري | لا قيد تفرد مطلوب |

الحقول وإلزاميتها وقيود التفرد والحالات وصلاحيات إجراءات الملف معتمدة من المستخدم. لا تُضاف حقول رواتب أو أرصدة أو مرفقات تلقائيًا؛ تُحدد في مهام وحداتها. التصميم المنطقي في [السيكما](DATABASE_SCHEMA.md)، وقواعد الحارس والإضافة والتعديل والحالات في [سياسة الصلاحيات](PERMISSIONS_POLICY.md). أطوال الأعمدة وأنواع SQL وتفاصيل واجهة الإدخال تبقى في مهام التصميم الفني.

## صلاحيات المسار ونطاقه

| الإجراء | القاعدة المعتمدة والتصميم المرتبط |
| --- | --- |
| استعراض الدليل وعرض الملف | مدير النظام والموارد البشرية، في جميع الفروع، والحقول المعتمدة؛ employees.read |
| إضافة موظف | كلا الدورين؛ employees.create مع الحقول الإلزامية والمراجع والتفرد والحالات المعتمدة |
| تعديل بيانات الملف | كلا الدورين؛ employees.update مع فحص النطاق والتفرد وقائمة الحقول المسموحة |
| تغيير الحالة | كلا الدورين؛ employees.change_status مستقلة، ولا تمرر ضمن التعديل العام |
| بيانات الإقامة والجواز والبصمة | ضمن حقول الملف المسموحة لكلا الدورين؛ لا تنسخ قيمها كاملة إلى السجل الفني |

المفاتيح التنظيمية موثقة في سياسة الصلاحيات، ولم تُنفذ برمجيًا. الشاشات والطلبات تعتمد على الحارس نفسه؛ لا تثق الخدمة بفرع أو دور يرسله العميل دون تحقق. تخصيص مستخدم محدد بالمنح أو المنع يتقدم على منح الدور بالقاعدة المعتمدة.

## الترقيم والتدقيق والأخطاء

- تُحفظ الأرقام الوظيفية الحالية، وتدخل الإدارة أرقام الموظفين الجدد يدويًا مع منع التكرار. لا يستدعي هذا المسار مركز الترقيم ولا يفرض صيغة سنوية على الرقم الوظيفي. لم يُطلب استيراد جماعي. تصميم السلاسل الأخرى في [مركز الترقيم](NUMBERING_DESIGN.md).
- تُحدد أحداث إضافة الملف وتعديله وقراءته ورفض الوصول إليه، ومستوى تسجيل استعراض الدليل والحقول المستبعدة من التدقيق. لا تسجل أسرار أو بيانات سرية.
- أخطاء الحقول وعدم الصلاحية والتكرار وتعذر الحفظ تُعرض برسائل عربية وإنجليزية ملائمة، مع تفاصيل فنية محمية ومعرف تتبع عند استخدامه.
- تُحسم المعاملات وكتابة التدقيق وآثار فشلها في تصميم الإضافة والتعديل قبل البرمجة.

## الاستعلامات والفهارس ومعيار الأداء

الاستعلامات المقترحة: قائمة ضمن النطاق وصفحات، وفتح ملف، وبحث رقم أو اسم وتصفية. يختار المستخدم الفرع ثم قسمه؛ قيد مركب يمنع تعارضهما في القاعدة. يربط [كتالوج الاستعلامات](DATABASE_QUERIES_AND_PERFORMANCE.md) مسارات الوصول بالفهارس ومعايير الأداء المقترحة. دلالة البحث بالاسم وشكل الصفحات مقترحات قبل الشاشة. تفرد الرقم والبصمة يطبق على مفتاح مقارنة يتجاهل حالة الحروف والمسافات الطرفية وفق قرار المستخدم، ولم تطبق القيود بعد.

تُبنى خطة الفهارس على هذه الاستعلامات وحجم البيانات والتفرد المعتمد. لا تُخترع أسماء فهارس أو ترتيب أعمدة قبل تصميم الجدول، ولا يُعد البحث الجزئي بالاسم محسومًا بمجرد إضافة فهرس. يُحدد زمن استجابة مستهدف وظروف قياسه بعد معرفة الحجم، وتسجل خطط EXPLAIN والقياسات في ملف السيكما عند التنفيذ.

## معايير قبول المسار

| المعرف | الحالة | النتيجة المطلوبة عند اعتماد وتنفيذ المسار |
| --- | --- | --- |
| E-01 | مستخدم مخوّل يضيف بيانات صحيحة | يحفظ الموظف في الفرع والقسم المسموحين ويظهر ضمن نطاقه بعد إعادة تحميل البيانات |
| E-02 | بيانات ناقصة أو غير صالحة | رفض مفهوم باللغة المختارة، دون سجل موظف جزئي أو تفاصيل تقنية مكشوفة |
| E-03 | قيمة مكررة في حقل اعتمد تفرده | منع التكرار على الخادم والقاعدة برسالة ملائمة؛ لا يعتمد على تحقق المتصفح وحده |
| E-04 | مستخدم دون صلاحية إضافة أو تعديل | رفض الطلب المباشر، وعدم تغيير البيانات، وتدقيق النتيجة حسب السياسة |
| E-05 | معرف موظف خارج نطاق المستخدم | منع القراءة والتعديل وعدم تسريب بياناته عبر الدليل أو الرسائل |
| E-06 | تعديل مسموح لملف | حفظ البيانات المسموح بها وتسجيل الحدث والقيم اللازمة وفق سياسة التدقيق |
| E-07 | البحث والتصفية وتقسيم الصفحات | نتائج صحيحة ضمن النطاق مع ترتيب متفق عليه وقياسات أداء موثقة |
| E-08 | إدخال أرقام الموظفين الحالية | تحفظ القيم دون إعادة ترقيم، ويمنع تكرار الرقم أو بصمة غير فارغة مع التزامن |
| E-09 | العربية والإنجليزية والكمبيوتر والجوال | رسائل وحقول ومحاذاة واتجاه صحيحان، مع حفظ سلامة الدخول والصلاحيات |
| E-10 | تحقق التنفيذ والبيانات | اختبارات مناسبة، وتعريفات Drizzle وترحيل وسيكما متزامنة، وفحص فعلي لما يتوقف على القاعدة |
| E-11 | موظف دون بيانات اختيارية | يسمح بالحفظ عند اكتمال الحقول السبعة الإلزامية؛ يمكن ترك رقم البصمة وبقية الاختياري فارغًا |
| E-12 | تكرار رقم وظيفي أو رقم بصمة غير فارغ | يرفض التكرار على مستوى المنشأة، حتى إذا اختلف الفرع، بما يشمل الإنشاء المتزامن |
| E-13 | وجود عدة موظفين دون رقم بصمة | يسمح بأكثر من ملف بلا رقم بصمة؛ لا تتحول القيمة الغائبة إلى صفر أو رقم مشترك |
| E-14 | تغيير الحالة لمخول | انتقال بين نشط وغير نشط مع حفظ الملف والأرقام والأثر؛ لا حدث انتقال مكرر عند طلب الحالة الحالية |
| E-15 | منع خاص بالمستخدم أو محاولة تغيير الحالة من التعديل العام | تطبيق المنع حتى لمدير النظام، وعدم تجاوز صلاحية تغيير الحالة |

هذه معايير للتنفيذ والاختبار وليست نتائج اختبارات ناجحة. حالات الحارس التفصيلية في سياسة الصلاحيات، وتضاف لها بيانات الاختبار الفنية عند بناء الوحدة.

## حالة الجاهزية

اكتملت متطلبات المسار والصلاحيات، وصُمم الدخول والتدقيق والترقيم، ووُثق [قاموس SQL](DATABASE_SQL_DESIGN.md) والفهارس والاستعلامات كتصميم فني مقترح للمراجعة. تبقى مراجعة المقترحات وتنفيذ Drizzle والترحيلات والاختبارات في مهام البناء؛ لا جدول أو فهرس أو حارس مطبق بعد. أرقام الموظفين الحالية والجديدة يدوية ولا تحتاج سلسلة آلية.
