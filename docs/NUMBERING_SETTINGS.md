## فحص kamal والقبول — C-139

ثبت kamal/hr في مساحة العمل، ثم حوّله الرابط المباشر /settings/numbering إلى /organization، ولم يظهر عنوان السلاسل أو رابطها أو نموذجها. فتح numberingSettings.list من الجلسة نفسها أظهر JSON AUTH_FORBIDDEN وdata.httpStatus403 دون result. بقيت جلسته صالحة بعد المنع والتحديث والعودة إلى المساحة، مع رابط التنظيم فقط. أُغلق تبويب API وأعيدت الصفحة المسموحة دون تغيير بيانات أو حسابات أو إعدادات أو قراءة أسرار. قبل المستخدم الدفعة وفق D-074؛ انتهى انتظار الدخول والفحص والقبول في سجلات C-138 وC-135 التاريخية أدناه. حدود الاختبارات المعزولة وغياب CRUD/إصدار إنتاجي باقية.

## متابعة النشر وADMIN — C-138

طابقت أصول C-135 ونجح /health والغلاف ورفض قائمة الإعدادات دون دخول401. الجلسة المتاحة ADMIN؛ نجح التنقل بين المساحة والصفحة، والقائمة فارغة. النموذج افتراضيه annual ومفعل وحشو4 والسنة2026 من الخادم، ورفض FSW محليًا، وأظهر Fsw-2026-0001 كمعاينة موسومة غير مصدرة أو محجوزة أو تالية. بقيت المسودة عند تبديل اللغة والحجم، ثم ألغيت وأعيد التحميل واكتملت القائمة فارغة. عرض390للإنجليزية375/375 وعرض320للعربية305/305، وأعيد الحجم والعربية.

لم تحفظ سلسلة أو يُرسل حفظ صالح، لذلك لا ادعاء لاختبار إنشاء/تعديل/تفرد/قفل على الإنتاج. تبقى نتائجها المعزولة في C-135. ينتظر منع kamal وتوجيهه دخوله الخاص ثم يكمل المساعد وفق D-070 ويطلب قبول الدفعة. لا كلمة أو دور أو صلاحية أو إصدار أو كود أو مخطط تغير في هذه المتابعة، ولا قبول تلقائي من طلب التالي.

## السلوك والحدود

قائمة إعدادات السلاسل بصفحات، وإنشاء سلسلة برمز نوع مستند وبادئة وسياسة عد وتفعيل، وتعديل بادئتها وسياسة العد قبل أول إصدار، وتفعيلها أو تعطيلها مع حفظ التاريخ. لا حذف، أو تغيير code بعد الإنشاء، أو إعادة ضبط عداد أو تعديل رقم صادر. لا نقطة API لإصدار أو حجز رقم، ولا إنشاء سلسلة أعمال افتراضية من الأمثلة. محرك الإصدار وربطه بإنشاء مستند حقيقي وإيصالات إعادة الطلب دفعة لاحقة بعد قبول الإدارة؛ لا يبنى محرك غير مستخدم أو يدعى اكتمال M3-03 هنا.

الرمز code معرف ثابت للنوع، إنجليزي من1إلى64حرفًا/رقمًا مع _ أو - ويبدأ بحرف، يحفظ بعد إزالة المسافات الطرفية، وتفرده مطابق لقيد ascii_bin القائم دون تحويل حالة صامت. البادئة بالضبط3أحرف لاتينية: الأول كبير والآخران صغيران مثل Fsw، وفريدة بين السلاسل حتى المعطلة. إدخال FSW يرفض برسالة واضحة، ولا تحول بادئات قائمة تلقائيًا. لا اسم عربي لنوع المستند في المخطط الحالي ولا حقل جديد ضمن هذه الدفعة؛ تعرض الواجهة «رمز نوع المستند» وتوضح ضابطه.

الصيغة {PREFIX}-{YYYY}-{SEQ} وحشو4خانات ثابتان في الإنشاء وفق Fsw-2026-0001؛ لا اقتطاع إذا تجاوز العدد9999 عند تنفيذ الإصدار لاحقًا. السياسة الافتراضية annual، وخيار continuous المعتمد يستمر فيه العداد مع ظهور سنة الإصدار. السنة من وقت الخادم وفق Asia/Riyadh، والتواريخ تخزن UTC. تعرض معاينة شكل موسومة مثالًا فقط وليست رقمًا صادرًا أو حجزًا. لا طلب تسلسل أو قراءة عداد للمعاينة.

بعد وجود أول سجل numbering_issuances للسلسلة يمنع الخادم تعديل prefix أو format أو padding_width أو reset_policy. يبقى enabled قابلًا للتغيير دون تحرير الرقم أو البادئة. الحالة hasIssued معلومة نعم/لا لإظهار القفل، لا عدد إصدارات أو وصول إلى بيانات المستندات. لا تتغير نسخة السجل عند حفظ مطابق؛ الحفظ الفعلي يزيد version مع فحص expectedVersion وحد النوع.

## الصلاحيات والتدقيق والأخطاء

settings.manage لكل قائمة وإنشاء وتعديل في نطاق منشأة المستخدم؛ لا تعتمد على organization.read أو اسم ADMIN. الموارد البشرية ممنوعة افتراضيًا، ويمكن تخصيص الصلاحية وفق السياسة القائمة. CSRF وOrigin والتحقق النهائي من الجلسة والمنح والمنع داخل المعاملة؛ لا تغيير جلسات أو auth_version بسبب إعدادات الترقيم. لا إعادة تأكيد كلمة إضافية لهذه الدفعة، مماثلة لإدارة إعدادات الفروع القائمة.

القائمة حدث واحد لكل طلب، والتغيير يسجل القيم الآمنة قبل/بعد مع entityVersion؛ الحفظ المطابق يسجل طلبًا مع changed:false دون أثر تغيير وهمي. نجاح الحفظ والتدقيق الاحتياطي شرط ذري؛ فشل outbox يتراجع معه الحفظ. تسجل حالات المنع والتعارض المتوقعة ضمن حدود الخدمة دون نسخ الأسرار أو SQL. تضارب code/prefix رسالة عربية/إنجليزية محددة، وتعارض النسخة يطلب إعادة تحميل الحالة. النتيجة غير المؤكدة لا تعاد آليًا؛ يطلب مراجعة القائمة قبل محاولة أخرى. رفض صفحة يستعمل عقد الحارس الحالي، ورفض إجراء يبقي الصفحة ورسالة الرفض مع تحقق خلفي محدود.

## الاستعلامات والفهرسة والأداء

لا تعديل بنيوي مخطط؛ قائمة السلاسل تستخدم PRIMARY(id) مع cursor/order/limit26. قراءة السلسلة وقفلها وتحديث نسختها تستخدم PRIMARY. قيدا uq_numbering_series_code وuq_numbering_series_prefix يحميان التفرد النهائي، بما في ذلك السلاسل المعطلة. فحص وجود أول إصدار يستخدم بادئة series_id في uq_numbering_issuances_sequence(series_id,period_key,sequence_value) مع LIMIT1؛ لا COUNT أو تحميل سجلات مستندات. يمكن إرجاع hasIssued بإسقاط EXISTS مفهرس لكل صف من الصفحة. لا فهرس إضافي أو مسح عدادات.

التعديل يقفل صف السلسلة أولًا ثم يفحص وجود إصدار؛ محرك الإصدار اللاحق ملزم بقفل الصف نفسه قبل تخصيص رقم. فحص الذاكرة لا يثبت ذلك على TiDB. تُراجع خطط EXPLAIN والأقفال والميزانيات في DATABASE_QUERIES_AND_PERFORMANCE.md قبل قبول الأداء الفعلي، ولا تستخدم بيانات الإنتاج التجريبية لهذا القياس. لا تدعي هذه الدفعة تفرد إصدار متزامن أو إيصالات إعادة إرسال لم تبن بعد.

## معايير التحقق والتسليم

اختبارات تحقق الحقول والبادئة والحشو وسنة الرياض عند حد السنة، والتفرد والنسخة والحفظ المطابق وتثبيت الإعدادات بعد وجود إصدار والتفعيل والتعطيل وعدم فقد التاريخ. اختبارات المنح الخاص والمنع الخاص وHR والمؤقت والمجهول وCSRF وOrigin وتغير صلاحية المنفذ، والتدقيق الذري والتراجع وعدم عرض أسرار. اختبارات المستودع تراجع SQL والمعاملات والفهارس دون وصفها كتجربة TiDB. يختبر سجل الحارس والمكوّن والتسمية وPWA للصفحة الجديدة.

متصفح معزول بالبيانات الاصطناعية للإنشاء والتعديل والتفرد والتعارض والقفل بعد الإصدار، واللغتين وعرض الجوال والتعافي والمسودة. تُنظف التجربة ويوقف خادمها، ثم تسلم النسخة للمستخدم لينشرها. المساعد يتحقق من النشر والمتصفح وفق D-070 باستخدام الجلسة المتاحة؛ قبول هذه الدفعة صريح مستقل. لا إنشاء أو تغيير سلاسل إنتاج أو بيانات مستندات تلقائيًا من أجل التجربة.
