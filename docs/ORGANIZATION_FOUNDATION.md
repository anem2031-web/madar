# الفروع والأقسام — جزء M3-02

## أحدث تعديل: حماية الإعادة D-080/C-165

استكملت حماية العمليات الأربع محليًا بمفتاحoperationId إلزامي وإيصال ذري مع الأعمال والتدقيق. تعاد نتيجة المحاولة المطابقة دون تغيير أعمال جديد، بعد الحارس وCSRF؛ يرفض المفتاح المختلف عن مدخله أو منفذه، والعميل القديم بلا مفتاح يرفض بـ400 ويحتاج تحديث الصفحة. يظل السماح بأسماء مكررة بمفاتيح محاولات مقصودة مختلفة، ونطاق الصلاحيات وتبعية القسم وحاجز المراجعة كما هي. لا تعميم على بقية الوحدات أو إضافة صفحة.

تفاصيل الملفات والمعاملات والاختبارات282والمتصفح في[تصميم الإصلاح](WRITE_REPLAY_FIX_PROPOSAL.md). يضيف الترحيل0001 جدولًا تقنيًا واحدًا بالمخطط المحلي، ولم يطبق علىTiDB. تراجع [السيكما](DATABASE_SCHEMA.md) و[دليل الإصدار](WRITE_REPLAY_DEPLOYMENT.md) قبل النشر؛ يلزم الترحيل والتحقق قبل العميل والخادم الجديدين، وإعادة تحميل التبويبات القديمة. ما يأتي أدناه يوثق دفعة التنظيم الأصلية المقبولةD-071؛ لا يعد قبولها قبولًا تلقائيًا للإصلاح الجديد أو إثباتًا لأقفالTiDB.

الحالة: نُفذ النطاق واختبر محليًا وفق C-122، ثم نُشرت النسخة وطابقت البناء وفُحصت بجلسة ADMIN وفق C-132 وkamal وفق C-133، وقبلها المستخدم صراحة وفق D-071. لا يُطلب القبول مجددًا. لم تُنشأ بيانات اختبار أو تغير أسماء المنشأة؛ جُرب الحفظ المطابق فقط في الإنتاج. لا يمثل هذا بدء وحدة الموظفين أو قياس TiDB أو الأجهزة.

## استكمال الفحص والقبول — C-133

قرأ kamal/hr الفرع وقسمًا تابعًا له، ولم تظهر أدوات الإضافة أو إعادة التسمية أو أي نموذج. حوّله الحارس عند طلب رابط إدارة محظور إلى الفروع والأقسام وثبت التحديث والرجوع. نجحت اللغتان وعرض الجوال وأُعيدت العربية والحجم. قبل المستخدم الجزء وفق D-071؛ انتهى انتظار دخوله وفحصه المذكور تاريخيًا في C-132 أدناه. لم يُرسل طلب كتابة تنظيمي من HR ولم يُختبر CRUD إنتاجي فعلي أو قفل TiDB من هذه المتابعة.

## فحص النسخة المنشورة — C-132

نجحت قراءة الفرع وقسمه وفتح نموذجي إعادة التسمية وحفظ القيم نفسها برسالة لم يحدث تغيير. منع النموذج الاسم الفارغ برسالة عربية، ثم بقيت مسودة غير محفوظة عند تبديل اللغة والحجم وإعادته، وأُلغيت دون إرسالها. اختفى نموذج مرة في تتابع عرض سابق ولم يتكرر في إعادة مركزة، ولم يُثبت له سبب من المصدر؛ لا تصحيح عيب مدعى. نجح فحص RTL/LTR وعرض الجوال؛ لا لمس أو تثبيت أو قياس TiDB. فحص قراءة HR ومنع تحريره ينتظر دخوله؛ الإضافة والتعديل الفعليان اختبرا ببيانات معزولة سابقًا ولم يجربهما المساعد ببيانات المنشأة ضمن C-132.

## النطاق والقبول

قائمة فروع بصفحات، إضافة اسم فرع وتعديل اسمه، واختيار فرع ثم قائمة أقسامه وإضافة اسم قسم وتعديل اسمه داخل الفرع نفسه. الاسم وحده حقل أعمال: نص غير فارغ بعد trim وبحد150محرفًا، مع حفظ العربية والإنجليزية دون ترجمة أسماء البيانات تلقائيًا. لا تفرد أسماء أو دمج مرجعين أو حذف أو تعطيل أو نقل قسم أو حقول اتصال إضافية؛ لا تغير ملفات الموظفين أو مراجعها بسبب إعادة تسمية.

معيار القبول: يضيف المدير المخول فرعًا وقسمًا تابعًا له ويعدل اسميهما ويحفظهما، وتعرض الموارد البشرية القوائم دون تعديل افتراضيًا. لا تعرض أقسام فرع آخر، ولا يقبل تعديل القسم بمعرف فرع مختلف أو طمس تعديل متزامن. يربط كل طلب بالحارس والتدقيق ويستعيد العرض من خطأ الشبكة برسالة مترجمة دون انتظار دائم أو إعادة حفظ تلقائية. تُسلم الدفعة وحدها للمستخدم بعد التحقق المحلي وتنتظر تجربته وقبوله.

## الملفات والعقود

- server/modules/organization: store وrepository وservice وvalidation وroutes وerrors وtests، مع auth والمعاملة والاتصال المركزيين. client/src/modules/organization للشاشة وحالة الطلبات والترجمات في shared/i18n/ar وen. ربط /organization بـAuthScreen وApp والتنقل وغلاف Express وتنقل PWA العام؛ لا تخزين بيانات محمية.
- organization.listBranches({cursor?}) -> {branches:[{id,name,version}],nextCursor?}،25صفًا وحد جلب26.
- organization.listDepartments({branchId,cursor?}) -> {branch:{id,name,version},departments:[{id,branchId,name,version}],nextCursor?}،25صفًا وحد جلب26. الفرع يجب أن يوجد، والقسم مقيد به.
- organization.createBranch({name}) -> {branch}؛ organization.renameBranch({branchId,expectedVersion,name}) -> {changed,branch}.
- organization.createDepartment({branchId,name}) -> {department}؛ organization.renameDepartment({branchId,departmentId,expectedVersion,name}) -> {changed,department}.
- ترفض الحقول الزائدة والمعرفات/النسخ غير الصالحة والأسماء الفارغة أو الطويلة. لا يقبل العميل كتابة version التالي أو التواريخ أو نقل branchId ضمن تعديل القسم. التعديل المطابق بعد trim يعيد changed:false دون زيادة version، مع حدث طلب لا يدعي تغييرًا.

## الصلاحيات والأمان والتدقيق والترقيم

قراءة القوائم تتطلب organization.read ونطاق جميع فروع المنشأة، وفق السياسة القائمة. الإنشاء وإعادة التسمية يتطلبان settings.manage وorganization.read معًا لأن النتيجة تعيد بيانات المرجع؛ لا يؤدي منح الإعدادات إلى تجاوز منع القراءة. لا تغيير لمنح الأدوار أو catalog أو تخصيصات المستخدمين. تتحقق الواجهة لعرض الأزرار ويعيد الخادم فحص الجلسة والسياسة الحالية في معاملة العمل. لا استثناء باسم ADMIN أو رمز الدور.

كتابة بيانات المرجع العادية تستخدم الجلسة المصادقة وCSRF وOrigin، دون إضافة تحدي كلمة مرور خاص بها؛ إعادة تحقق الحسابات الحساسة تبقى في وحداتها. تحفظ المعاملة الإنشاء/التعديل وحدث audit_outbox معًا؛ فشل outbox يرجع البيانات. التعديل يقارن expectedVersion ويزيد version فقط عند تغير الاسم، ويمنع القيم الخارجة عن سعة INT UNSIGNED. لا إبطال لجلسات أو تغيير auth_version بسبب إعادة تسمية مرجع.

التدقيق module=organization: أحداث قائمة فروع وقائمة أقسام لكل طلب، وإضافة وإعادة تسمية الفرع/القسم والرفض. entityId هو معرف المرجع، وentityVersion لنسخته المشاهدة أو الناتجة عند توفرها، وbefore/after للاسم والفرع والنسخة، وmetadata محددة للنوع/count/changed عند الحاجة. قائمة أقسام فرع تربط هوية الفرع ونسخته ونوعه، ولا تنسب معرف الفرع إلى قسم. لا كلمات أو رموز أو بيانات موظفين. يستخدم حقل entity_version الموجود دون تغيير مخطط أو إعادة كتابة تدقيق قديم؛ عامل النقل الكامل ضمن M3-04. لا أرقام أعمال لهذه المراجع ولا طلب لتسلسل جديد؛ UUID داخلي فقط.

## البيانات والاستعلامات والفهارس

تستخدم branches وdepartments القائمة في database/schema/organization.ts، وusers والمنح والجلسات للحارس وaudit_outbox. لا جدول/حقل/علاقة/فهرس/ترحيل أو إعداد CHECK جديد. تعرف الأقسام الفرع بمرجع ثابت، ولا ينفذ حذف أو نقل. تسمح البنية الحالية بأسماء متكررة؛ لا يضاف منع تكرار صامت أو فحص لا يحميه قيد.

فروع مرتبة id وid>cursor عبر PRIMARY(branches.id). أقسام مقيدة branch_id وid>cursor وترتيبid عبر uq_departments_branch_id(branch_id,id). قراءة وتعديل مرجع بمعرفه عبر PRIMARY مع شرط expectedVersion، وتعديل القسم يضيف branch_id لمنع تغيير قسم من فرع آخر. تعاد قراءة المراجع وتتحقق النسخة قبل الكتابة. لا بحث حر أو OFFSET أو COUNT تلقائي أو فرز أسماء يحتاج فهرسًا جديدًا. سيختبر عقد SQL المقيد والحدود والتراجع، وتظل EXPLAIN والأقفال والأداء على TiDB الفعلية معلقة إلى قاعدة اختبار منفصلة ببيانات ممثلة و10 مستخدمين متزامنين؛ هدف القراءة المقترح ثانية p95 ولا نجاح أداء مدعى.

## الواجهة والأخطاء والاختبارات

عربية RTL وإنجليزية LTR وتخطيط متجاوب مع أسماء البيانات كما أدخلت. اختيار الفرع يلغي قائمة/مسودة القسم القديم ونتائجه المتأخرة؛ ربط القسم دائم بفرعه في النص والنموذج. الموارد البشرية تقرأ دون نماذج كتابة افتراضيًا. تعطل الأفعال أثناء التحقق الخلفي والحفظ، وتبقى مسودة الحساب نفسه في التحقق العادي. لا تظهر بيانات لحساب جديد أو جلسة منتهية.

تثبت مؤشرات الصفحات وتاريخها عند نجاح الطلب فقط. عند تعارض النسخة يطلب إعادة تحميل الحالة قبل إعادة التعديل؛ عند نتيجة حفظ غير مؤكدة يمنع الإرسال المتكرر حتى إعادة تحميل ومراجعة القوائم لأن أسماء المراجع غير فريدة. لا نجاح مفترض عند خطأ شبكة، ولا إعادة إرسال إنشاء صامتة. الرسائل مترجمة للحقل والنسخة القديمة وعدم وجود الفرع/القسم والمنع وفشل الاتصال والنتيجة غير المحسومة، بلا SQL أو تفاصيل أسرار.

اختبارات Vitest للخدمة والمشغل وHTTP: الجلسات غير المخولة/التمهيدية/المؤقتة، HR قراءة فقط، المنع الخاص على المدير والمنح الخاص وفق الحارس، فصل القراءة والكتابة، CSRF/Origin والتحقق الصارم، trim والعربية/الإنجليزية وحد150محرفًا، السماح بالأسماء المتكررة دون سياسة جديدة، فرع غير موجود وقسم من فرع آخر، expectedVersion والتعديل المطابق وتعديلان متزامنان، فشل الأعمال/outbox والتراجع وعدم إبطال الجلسات، خصوصية الأخطاء وعقود الاستعلام. فحص متصفح معزول للإنشاء والتعديل والفرع ثم أقسامه والمنع واللغتين والعروض الضيقة والتعافي؛ لا بيانات تجارب في إنتاج المنشأة ولا ادعاء نجاح TiDB من mocks.
