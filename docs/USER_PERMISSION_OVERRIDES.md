# تخصيص صلاحيات المستخدم — جزء M3-02

الحالة: نطاق التنفيذ مثبت قبل البرمجة بتاريخ 2026-11-23 وفق D-062 إلى D-064. نُفذ الجزء واختبر محليًا وفق C-118؛ ينتظر نشر المستخدم وتجربته وقبوله. يقرأ معها ملفا PERMISSIONS_POLICY.md وSECURITY_AND_AUDIT_DESIGN.md والسيكما وكتالوج الأداء.

## النطاق ومعيار القبول

تظل أدوار مدير النظام والموارد البشرية ومنحها الحالية دون تحرير. تعرض الشاشة حسابات المنشأة بصفحات، ثم الدور ومنحه وتخصيصات الحساب المختار. لكل صلاحية معروفة ثلاث حالات: حسب الدور (غياب التخصيص)، سماح خاص (grant)، منع خاص (deny). يعيد الخادم النتيجة الفعلية من الحارس المركزي. يمنع تعديل تخصيصات حساب المنفذ نفسه؛ يتولاها مدير آخر مخول. لا إنشاء أدوار أو صلاحيات أو وحدات جديدة، ولا تعديل دور الحساب أو حالته أو كلمته من هذه الشاشة.

القبول المطلوب: يستطيع المخول حفظ تخصيصات حساب آخر وإعادتها للوراثة، ويمنع غير المخول حتى بالطلب المباشر، ويتقدم المنع الخاص على منح الدور دون تجاوز لمدير النظام. يظهر التعديل عند الدخول التالي للحساب المستهدف، وتبطل جلساته القديمة؛ لا حفظ جزئي عند فشل التدقيق أو تعارض النسخة. تُجرب العربية والإنجليزية والجوال قبل تسليمها للمستخدم ثم ينتظر قبوله الصريح.

## الملفات والعقد

- server/modules/permission-overrides: store للعقد، repository للاستعلامات، service للقواعد والمعاملات، validation للتحقق، routes وerrors للتحويل الآمن، tests للاختبارات المعزولة. يعاد استخدام authorizeInTransaction وcheckMutation ومحرك الصلاحيات القائم والاتصال المركزي.
- client/src/modules/permission-overrides: شاشة وحالة اتصال وترجمة؛ shared/i18n/ar وen لنصوصها. مسار /permissions وربطه بالتنقل وAuthScreen وغلاف Express وقائمة تنقل PWA العامة، دون تخزين البيانات المحمية.
- permissionOverrides.list: cursor اختياري، 25 حسابًا فقط مع معرف واسم ودور وحالة ونسخة اعتماد آمنة. لا كلمات أو hashes أو رموز أو بيانات موظفين.
- permissionOverrides.detail: userId؛ يعيد الحساب الآمن والمنح والتخصيصات والنتيجة الفعلية وكون التعديل متاحًا. قائمة رموز الصلاحيات من catalog المشترك وحده.
- permissionOverrides.save: userId وexpectedAuthVersion وكلمة المنفذ الحالية وقائمة كاملة من التخصيصات الصريحة grant/deny. غياب الرمز يعيد الوراثة؛ ترفض الحقول الزائدة والرموز المجهولة والتكرار والقيم غير المعتمدة. يعيد الحالة الآمنة بعد الحفظ، دون إعادة الكلمة. الحفظ المطابق للحالة الحالية لا يغير النسخة أو الجلسات ويسجل الطلب بنتيجة no-change آمنة.

## الضوابط والبيانات

كل قائمة وقراءة وحفظ تتطلب permissions.manage_overrides وجلسة مصادقة كاملة على الخادم؛ users.manage أو اسم الدور وحده لا يكفي. النطاق جميع حسابات المنشأة، دون صلاحيات ضمنية للوظائف الأخرى. إعادة تحقق بكلمة المنفذ وبعداد دائم 5 محاولات خلال15دقيقة، وCSRF وOrigin؛ حد الدقيقتين يخص الدخول وحده. يعاد فحص المنفذ وكلمته ونسخته وصلاحيته داخل معاملة الحفظ.

تستخدم users وroles وrole_permissions وpermissions وuser_permission_overrides وsessions وauth_throttles وaudit_outbox الموجودة. لا DDL أو فهرس أو ترحيل أو تغيير CHECK أو إعداد قاعدة مخطط. تقفل قراءة الهدف ومنحه وتخصيصاته، ثم تقارن auth_version وتزيده عند تغير فعلي؛ تحفظ مجموعة التخصيصات وإبطال جلسات الهدف وحدث outbox ذريًا. إرجاع الوراثة يحذف صف التخصيص المعني فقط بعد طلب حفظ صريح، ولا يحذف حسابات أو تاريخ تدقيق. أي فشل غير متوقع يتراجع دون نجاح جزئي، والتعارض يعاد كرسالة لإعادة تحميل الحالة دون إعادة إرسال صامتة.

لا ترقيم أعمال لهذا الجزء؛ معرفات الحسابات والأحداث الداخلية القائمة تكفي. التدقيق يسجل طلب قائمة واحدًا وفتح حساب واحدًا والحفظ والرفض مع هوية المنفذ ونسخة الهدف والرموز والآثار الآمنة قبل/بعد. تستبعد كلمات التأكيد وhashes والرموز والأسرار. عامل نقل outbox والبحث الشامل في التدقيق يبقيان M3-04.

## الاستعلامات والفهارس والأداء

القائمة مرتبة حسب users.id مع id>cursor وحد26 للاستفادة من PRIMARY، وربط الدور عبر PRIMARY(roles.id). قراءة الهدف عبر PRIMARY(users.id)، منح الدور عبر PRIMARY(role_id,permission_code)، والتخصيصات عبر PRIMARY(user_id,permission_code). تحديث auth_version مشروط بالمعرف والنسخة، واستبدال تخصيصات الهدف ببادئة user_id وإبطال جلساته ببادئة ix_sessions_user_expiry. لا بحث حر أو OFFSET أو فهرس إضافي. تقارن مجموعة لا تتجاوز رموز catalog الحالية قبل الكتابة لتجنب تحديثات بلا تغير.

المعيار الفني المقترح للقياس: قراءة الصفحة/التفاصيل ضمن ثانية p95، وقياس الحفظ شامل scrypt والتدقيق منفصلًا على 10 مستخدمين متزامنين. لا يُدعى تحقق هذا الرقم قبل EXPLAIN وقياسات على TiDB اختبار منفصلة ببيانات ممثلة؛ بيانات التجربة لا تدخل إنتاج المنشأة. إلى حين تجهيز بيئة الاختبار تسجل حدود اختبارات المشغل والذاكرة والمتصفح بوضوح.

## الواجهة والأخطاء والاختبارات

الواجهة عربية RTL وإنجليزية LTR ومتجاوبة، مع أسماء للصلاحيات وحالات الوراثة والسماح والمنع ونتيجة الخادم. تظهر هوية صاحب كلمة التأكيد بوضوح، وتقرأ الكلمة من الحقل الفعلي عند الإرسال دون trim، ثم تمسح من DOM والحالة، وتمسح عند إخفاء التبويب. لا مسودة محفوظة في المتصفح، وتتعطل الإجراءات أثناء التحقق الخلفي والحفظ، وتلغى النتائج القديمة عند تبديل الحساب أو الصفحة. لا حساب ذاتي قابل للحفظ ولا تعديل خفي للدور.

رسائل مترجمة للتحقق والمنع والتعديل الذاتي والنسخة القديمة وفشل التأكيد وكثرة المحاولات وتعذر الخدمة/الشبكة، دون SQL أو stack أو أسرار. يشمل الاختبار: HR افتراضيًا وطلب مباشر دون صلاحية، المنع الخاص على المدير، منح الخاص على HR، مؤقت/تمهيدي، CSRF، المدخلات المجهولة/المكررة، منع الذات، تعارض النسخة وتغير صلاحية المنفذ أثناء التحقق، إبطال جلسات الهدف فقط، الوراثة والحفظ المطابق، rollback عند فشل outbox، الخصوصية في النتائج والتدقيق، وعقود SQL. اختبار المتصفح ببيانات معزولة فقط مع اتجاهين وعرض جوال؛ لا ادعاء نجاح TiDB من mocks.
